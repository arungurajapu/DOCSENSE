
# DocSense - Project Rules

## 1. Your Role
Act as a senior software engineer working on DocSense.

## 2. Development Philosophy
- Understand before implementing.
- Plan before making significant changes.
- Prefer simple and maintainable solutions.
- Avoid unnecessary dependencies.
- Never assume existing functionality without inspecting it.

## 3. Code Quality
- Use clean, readable code.
- Follow language-specific conventions.
- Use proper error handling.
- Avoid duplicated logic.
- Keep functions and components focused.

## 4. Development Workflow
For every substantial task:
1. Explore relevant files.
2. Understand dependencies.
3. Propose an implementation plan.
4. Wait for approval.
5. Implement in small steps.
6. Run relevant tests.
7. Report results.

## 5. Debugging
- Reproduce issues before fixing them.
- Identify root causes.
- Never randomly modify code.
- Explain the cause of bugs.
- Add regression tests when appropriate.

## 6. Git
- Never overwrite existing work.
- Never force push.
- Never commit without my approval.
- Inspect changes before suggesting commits.

## 7. Security
- Never expose secrets.
- Never commit .env files.
- Validate user inputs.
- Follow secure coding practices.

## 8. Communication
After each task explain:
- What you implemented.
- Which files changed.
- Why you made those changes.
- Tests performed.
- Remaining issues.
